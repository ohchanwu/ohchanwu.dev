  • 2026-now
    Jobcron

    Goal: Jobcron gathers entry-level developer postings from Korean job boards into one daily briefing, with an explained fit score for each post. Infra: A Go binary runs as an invite-only beta on EC2 and private RDS (PostgreSQL) managed with Terraform, and its first production deployment was gated on restoring an encrypted backup. It was built through harness engineering with multiple AI agents.

    목적: 국내 채용 포털에 흩어진 신입 공고를 매일 하나의 브리핑으로 모으고, 공고마다 근거가 설명된 적합도 점수를 제공합니다. 구조: Go 바이너리를 Terraform으로 관리하는 EC2와 프라이빗 RDS(PostgreSQL)에 배포해 초대 전용 베타로 운영하며, 첫 운영 배포는 암호화 백업 복원에 성공한 뒤 승인했습니다. 여러 AI 에이전트를 활용한 하네스 엔지니어링으로 개발했습니다.

    AI Fit Scoring under Daily Spending Limits

    일일 비용 한도 안에서 동작하는 AI 적합도 평가

    Problem: AI scoring used to need each user’s own LLM API key, and every post had to be scored quickly and cheaply. Analysis: I chose an external question-answering model (TypeSafe Jev) for speed and cost: a paid probe on 30 synthetic posts measured a median 0.54 s and about USD 0.00013 per post. Solution: The server asks it fixed yes/no and scored questions about each post through an API, under per-user and total daily US-dollar limits, with a deterministic fallback. Result: It has been in production since October 30, 2026, and users no longer need an API key of their own.

    문제: 예전에는 사용자가 직접 LLM API 키를 넣어야 AI 평가를 받을 수 있었고, 모든 공고를 빠르고 저렴하게 평가해야 했습니다. 분석: 속도와 비용을 기준으로 외부 질의응답 모델(TypeSafe Jev)을 골랐고, 합성 공고 30개로 유료 측정한 결과 공고당 중앙값 0.54초, 약 USD 0.00013이 나왔습니다. 해결: 서버가 API로 공고마다 정해진 예/아니요 질문과 점수 질문을 보내고, 사용자별, 전체 일일 USD 한도 안에서 운영하며 결정론적 폴백을 제공합니다. 결과: 2026년 10월 30일부터 운영 중이며, 사용자는 자신의 API 키 없이 평가를 받습니다.

    Alpha-User Feedback to Shipped Releases

    알파 사용자 피드백을 릴리스로 반영

    Problem: On November 3, 2026, SSAFY classmates using the alpha sent feedback and screenshots, alongside my own requests. Solution: An orchestrator agent specified them as 28 items with a plan; after my approval, worker and reviewer agents implemented and reviewed the work. Release: It shipped in two releases: an application-only release on November 6, and a migration release after a manual RDS snapshot on November 7, which became the beta release. Result: By the November 8 update, these changes were deployed: listing cards with salary, location, and stack, wanted and unwanted conditions with signed points, saved filters, admin tools, and a redesign chosen with SSAFY classmates.

    문제: 2026년 11월 3일, 알파를 쓰던 SSAFY 동기들이 보낸 피드백과 스크린샷, 그리고 제 요청을 반영해야 했습니다. 해결: 오케스트레이터 에이전트가 피드백을 28개 항목의 스펙과 계획으로 정리했고, 제가 승인한 뒤 작업자 에이전트와 리뷰어 에이전트가 구현하고 검토했습니다. 배포: 애플리케이션만 바꾸는 릴리스(11월 6일)와 수동 RDS 스냅샷 뒤의 마이그레이션 릴리스(11월 7일)로 나눠 반영했고, 11월 7일 릴리스가 베타 릴리스가 되었습니다. 결과: 11월 8일 업데이트까지 연봉, 위치, 기술스택을 보여 주는 공고 카드, 점수가 붙은 선호 조건과 비선호 조건, 저장 필터, 관리자 도구, SSAFY 동기들과 함께 고른 새 디자인을 배포했습니다.

    Evidence Sentences for AI Ratings

    AI 점수의 근거 문장

    Problem: One alpha user said the points the AI added or removed for each condition were hard to trust, because the screen showed only the points and the condition the user had entered, with no evidence from the posting. Analysis: The model answers only choice and score questions and cannot write text. Working with an orchestrator agent, I proposed the designs, carried out 7 measurement runs on 3 postings and made every decision; AI agents wrote the measurement code and the feature. Solution: Jobcron splits each posting into numbered sentences, and a second request that states each rating and asks only for its main reason chooses the sentence numbers; it cannot change the rating and found a sentence for 21 of 25 lines. The model also returns a probability for every option, so the line shows sentences from the highest probability down until they add up to 0.7, at most 5, or a label when none is chosen. Result: Since November 6, 2026, each condition line that changes the score has shown those posting sentences unchanged as evidence.

    문제: 알파 사용자 한 명은 화면에 점수와 사용자가 입력한 조건만 있고 공고에서 나온 근거가 없어, 조건마다 AI가 더하거나 뺀 점수를 믿기 어렵다고 했습니다. 분석: 모델은 선택 질문과 점수 질문에만 답하고 텍스트를 쓸 수 없습니다. 오케스트레이터 에이전트와 함께 제가 설계를 제안하고 공고 3건으로 7차례 측정해 모든 결정을 내렸으며, 측정 코드와 기능은 AI 에이전트가 작성했습니다. 해결: 공고를 문장으로 나눠 번호를 붙이고 평가를 알려 준 뒤 주된 근거만 묻는 두 번째 요청으로 문장 번호를 고르게 했으며, 평가를 바꿀 수 없는 이 요청은 25줄 중 21줄에서 문장을 찾았습니다. 모델이 선택지마다 확률도 함께 돌려주므로, 확률이 높은 문장부터 합이 0.7이 될 때까지 최대 5개를, 고른 문장이 없으면 안내 문구를 보여 줍니다. 결과: 2026년 11월 6일부터 점수를 바꾸는 조건 줄마다 고른 공고 문장을 원문 그대로 근거로 보여 줍니다.
